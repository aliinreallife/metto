# Fix: Schedule data not rendering after lazy load

## Root cause
`loadScheduleData()` is un-awaited. When JSON fetch completes, the module cache is updated but React components have no way to know — they rendered with `[]` and stay that way.

## Solution: useScheduleData() hook

Create a React hook that subscribes to schedule data loading state. Components that need departure times call this hook and re-render when data arrives.

### Changes

1. **`lib/schedule-utils.ts`** — Add a listener system:
   - `onScheduleDataReady(callback)` — register a listener
   - `isScheduleDataLoaded()` — check if data is in cache
   - When `getScheduleData()` resolves, notify all listeners

2. **`lib/use-schedule-data.ts`** (new) — React hook:
   ```tsx
   function useScheduleData() {
     const [loaded, setLoaded] = useState(isScheduleDataLoaded);
     useEffect(() => {
       if (isScheduleDataLoaded()) return;
       return onScheduleDataReady(() => setLoaded(true));
     }, []);
     return loaded;
   }
   ```

3. **Components that need departures** — wrap in the hook:
   - `components/route-panel.tsx` — adds `useScheduleData()` to trigger re-render
   - `components/station-card.tsx` — adds `useScheduleData()`
   - `components/station-detail.tsx` — adds `useScheduleData()`
   - `components/station-timesheet.tsx` — adds `useScheduleData()`

4. **`app/providers.tsx`** — keep the background preload as-is (already works)

### Why this approach
- No code splitting needed (one JSON file is fine for 5.5 MB — it's cached after first load)
- Components show "loading" state briefly, then update with real data
- Subsequent visits use the cached data instantly (Service Worker + memory cache)
- Minimal code changes (hook + 4 components)
