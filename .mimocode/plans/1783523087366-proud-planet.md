# Plan: Fix Output Schemas and Annotations for Smithery

## Problem
Smithery scans the **HTTP endpoint** (`app/api/mcp/route.ts`), not the stdio `mcp-server.ts`. The HTTP route is missing `outputSchema` and `annotations` on all 4 tools. That's why Smithery shows warnings.

## Goal
Add `outputSchema`, `annotations`, and `structuredContent` to all 4 tools in `app/api/mcp/route.ts`.

## Files to Modify
- `/home/ali/tehran-metro-app/app/api/mcp/route.ts` — the HTTP endpoint Smithery actually scans

## What Changes

### 1. Add `outputSchema` to each tool

Each tool's `registerTool` config gains an `outputSchema` field using Zod object shapes. When `outputSchema` is set, the handler **must** also return `structuredContent` alongside the existing `content` text.

**`get_route`:**
```ts
outputSchema: {
  route: z.string(),
  stops: z.number(),
  transfers: z.number(),
  travelTimeMinutes: z.number(),
  path: z.array(z.string()),
  hops: z.array(z.object({ from: z.string(), to: z.string(), line: z.number() })),
}
```
Handler adds `structuredContent` with the parsed data from `findRoute()`.

**`list_stations`:**
```ts
outputSchema: {
  count: z.number(),
  stations: z.array(z.object({
    id: z.string(), name: z.string(), fa: z.string(), lines: z.array(z.number()),
  })),
}
```

**`get_station`:**
```ts
outputSchema: {
  id: z.string(), name: z.string(), fa: z.string(),
  lines: z.array(z.number()),
  coordinates: z.object({ lat: z.number(), lng: z.number() }),
  connectedTo: z.array(z.string()),
  amenities: z.array(z.string()),
}
```

**`find_nearby`:**
```ts
outputSchema: {
  results: z.array(z.object({
    station: z.object({ id: z.string(), name: z.string(), fa: z.string() }),
    distanceKm: z.number(),
  })),
}
```

### 2. Add `annotations` to each tool

All 4 tools are read-only metro data lookups — no mutations, no external API calls.

```ts
annotations: {
  readOnlyHint: true,
  destructiveHint: false,
  idempotentHint: true,
  openWorldHint: false,
}
```

### 3. Update handler return values

Each handler currently returns `{ content: [{ type: "text", text: ... }] }`. After adding `outputSchema`, each must also return `structuredContent` with the typed object. The text content stays for backward compatibility with clients that don't support structured output.

Example for `get_station`:
```ts
return {
  content: [{ type: "text" as const, text: ... }],
  structuredContent: {
    id: station.id, name: station.name, fa: station.fa,
    lines: station.lines,
    coordinates: { lat: station.lat, lng: station.lng },
    connectedTo: station.relations,
    amenities: [...],
  },
};
```
