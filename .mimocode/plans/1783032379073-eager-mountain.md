# Route Panel & Station Card Improvements

## Issues Identified

1. **Duplicate stop counts**: `route.numStops + 1` in top stats + `hops` in each SegmentCard + `stations.length` in expandable section
2. **Inconsistent station cards**: Stations-tab and nearby-tab have different card designs for the same data
3. **Unclear "Get there" button**: MapPin icon with "Get there" text isn't self-explanatory - users don't know it opens a maps app
4. **Route tab too packed**: Too much information compressed into small space
5. **Underutilized space**: Design could better use available screen real estate

---

## Solution Design

### 1. Unify Station Card Component

**New file**: `components/station-card.tsx`

Create a shared `StationCard` component used by both `StationsTab` and `NearbyTab`. The card design:
- Clean header with station name (primary language) + secondary name below
- Line badges with colored dots
- Expandable amenities section (only when amenities exist)
- Action buttons row at bottom

**Layout**:
```
┌─────────────────────────────────────────┐
│  ●●  Station Name                       │
│      Secondary Name                     │
├─────────────────────────────────────────┤
│  [Line 1] [Line 2] [Interchange]        │
├─────────────────────────────────────────┤
│  [🗺️ Open in Maps] [📍 From] [🚩 To]   │
└─────────────────────────────────────────┘
```

### 2. Fix "Get There" Button Clarity

**Problem**: `MapPin` icon + "Get there" text is ambiguous

**Solution**: 
- Change icon from `MapPin` to `ExternalLink` (clearer it opens external app)
- Change text from "Get there" to "Open in Maps" / "نقشه"
- Add tooltip explaining it opens Google Maps, Waze, etc.

**Files to update**:
- `lib/i18n.ts`: Change `navigate` string
- `components/station-card.tsx`: Use new icon and text
- `components/route-panel.tsx`: If "get there" exists there too

### 3. Simplify Route Panel Stop Counts

**Problem**: Three different stop counts visible:
- Line 38: `persianDigits(route.numStops + 1, lang)` 
- Line 154: `persianDigits(hops, lang)` per segment
- Line 211: `persianDigits(stations.length, lang)` in expandable

**Solution**:
- Keep only the top-level `route.numStops + 1` as the total
- Remove redundant per-segment stop counts OR consolidate to show only segment-specific hops
- The expandable section should show station names, not repeat stop count

### 4. Improve Route Tab Spacing

**Current issues**:
- Stats grid is cramped (3 columns, small padding)
- Segment cards are dense with small text
- Transfer indicators are tiny

**Proposed improvements**:
- Increase padding in stats grid: `px-2 py-2` → `px-3 py-3`
- Make segment cards taller with more breathing room
- Use larger font sizes for key info
- Add visual separators between segments
- Make the "X stops" expandable button larger and more tappable

### 5. Better Use of Space

**Current**: Cards use `rounded-xl border p-4` but content is still cramped

**Proposed**:
- Use `max-w-lg` or `max-w-xl` instead of `max-w-2xl` for better readability
- Increase vertical gaps: `gap-2` → `gap-3`
- Add more padding to cards
- Use consistent spacing rhythm (multiples of 4px)
